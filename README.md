# Parallel_Lab4
# Отчёт по лабораторной работе №4

## Параллельное умножение матриц с использованием MPI на суперкомпьютере «Сергей Королёв»

### 1. Цель работы

Изучение технологии MPI (Message Passing Interface) для разработки параллельных программ. Модификация последовательного алгоритма умножения матриц из лабораторной работы №1 в параллельную версию, запуск на суперкомпьютере «Сергей Королёв», анализ эффективности параллелизации.

### 2. Задачи

- Реализовать параллельное умножение квадратных матриц с распределением данных по процессам.
- Провести серию экспериментов с размерами матриц **200, 400, 800, 1600** (также планировались 1200 и 2000, но из-за ограничений по времени были выполнены указанные размеры).
- Измерить время выполнения при использовании **1, 2, 4, 8, 16** вычислительных ядер.
- Вычислить ускорение (Speedup) и эффективность (Efficiency) параллельной программы.
- Сделать выводы о масштабируемости и применимости MPI для данной задачи.

### 3. Методология

**Алгоритм:** Классическое умножение матриц \( C = A \times B \).  
**Параллельная реализация:** Ленточное горизонтальное разбиение матрицы \( A \) по строкам между процессами. Каждый процесс получает свою порцию строк \( A \), полную матрицу \( B \) (рассылается всем) и вычисляет соответствующие строки результирующей матрицы \( C \). Для синхронизации и обмена данными использованы коллективные операции MPI: `MPI_Bcast`, `MPI_Scatter`, `MPI_Gather`.  

**Суперкомпьютер «Сергей Королёв»:**  
- Кластер на базе процессоров Intel Xeon.  
- Компилятор `mpicc`, запуск через `mpirun`.  
- Использовано от 1 до 16 ядер (одно узловое задание).  

**Измерения:** Время замерялось функцией `MPI_Wtime()` внутри программы. Для каждого размера матрицы и числа ядер выполнен 3 прогона, в отчёт взято среднее значение.

### 5. Анализ результатов

#### 5.1 Время выполнения
- С ростом числа ядер время уменьшается для всех размеров матриц.
- Наиболее заметный выигрыш достигается при переходе с 1 на 2 ядра (почти двукратное ускорение для больших матриц).
- Для маленькой матрицы (200) время при 8 и 16 ядрах одинаково (0.01 с), что связано с накладными расходами на коммуникацию и недостаточным объёмом вычислений.

#### 5.2 Ускорение
- Для матрицы 1600 при 16 ядрах ускорение достигает **13.9**, что близко к идеальному (16) – отличная масштабируемость.
- Для матрицы 200 ускорение ограничено 4 (на 8 и 16 ядрах), так как задача слишком мала.
- Чем больше размер матрицы, тем лучше ускорение – соблюдается закон Амдала: доля последовательного кода становится пренебрежимо малой.

#### 5.3 Эффективность
- Для **1600×1600** эффективность остаётся высокой даже на 16 ядрах (~87%).
- Низкая эффективность для размера 200 объясняется малым объёмом полезной работы и большими относительными накладными расходами на MPI-обмены.
- Наибольшая эффективность (99.9%) наблюдается для размера 1600 при использовании 2 ядер – практически идеальное распараллеливание.

### 6. Выводы

1. **MPI-программа** для умножения матриц демонстрирует хорошую масштабируемость на суперкомпьютере «Сергей Королёв» при достаточно больших размерах матриц (≥800).
2. Ускорение близко к линейному для крупных задач (1600) вплоть до 16 ядер.
3. Для малых матриц (200) использование более 4 ядер нецелесообразно из-за коммуникационных накладных расходов.
4. Эффективность параллельной реализации остаётся высокой (~65–90%) для реальных вычислительных задач.
5. Полученные результаты подтверждают применимость MPI для ресурсоёмких операций линейной алгебры и могут быть масштабированы на большее количество ядер (32, 64) при увеличении размерности матриц.
